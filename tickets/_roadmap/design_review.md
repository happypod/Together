# Master Plan Design Review

- Review date: 2026-05-30
- Reviewed files: `master_plan.md`, `definitions.md`, `queue.md`, `status.json`
- Result: 초기 마스터플랜은 MVP 범위 정의로는 충분하지만, 구현 착수 전 기준으로는 보안, 운영 설정, 리포트 산식, API 계약, 모바일 링크 제어가 부족했다. 보완 사항은 반영 완료했다.

## 결론

현재 보완 후 마스터플랜은 MVP 제작을 시작할 수 있는 수준이다. 추가 기획이 필요한 영역은 남아 있지만, 대부분 구현 전 확정하면 되는 운영 정책이다.

## 발견한 부족한 점과 조치

| 구분 | 부족했던 점 | 조치 |
| --- | --- | --- |
| 사용자와 권한 | `createdByUserId`를 사용하지만 `User` 모델 기준이 없었음 | `User`를 핵심 모델에 추가하고 서버 권한 검증 원칙을 명시 |
| 모바일 링크 | 링크형 입력폼의 접근 범위, 만료, 보안 기준이 없었음 | `MobileFormToken` 모델과 scope, 만료, 사용 횟수 기준 추가 |
| 파일첨부 | 영수증 링크 또는 첨부의 메타데이터와 권한 기준이 약했음 | `FileAttachment` 모델과 파일 제한 기준 추가 |
| 운영 설정 | 기본요금, 그룹 최대 인원, 반올림 정책이 코드 상수로 굳어질 위험이 있었음 | `AppSetting` 모델과 초기 설정값 추가 |
| 운영 연락 | 실제 전화 확인과 변경 안내 기록이 빠져 있었음 | `ContactLog`를 보조 모델로 추가 |
| API 계약 | 기능명은 있었지만 권한, 감사로그, 검증 기준이 부족했음 | Server Action/API 계약 표 추가 |
| 데이터 검증 | 필드 목록 중심이고 업무 규칙이 부족했음 | 신청, 그룹, 택시예약, 운행, 정산 검증 규칙 추가 |
| 리포트 | KPI 목록은 있으나 지표 산식이 부족했음 | 월간 리포트 지표 계산 기준 추가 |
| 보안과 개인정보 | 마스킹과 CSV 기준은 있었지만 토큰, 보관, 삭제 기준이 약했음 | 인증, 개인정보 표시, 보관과 삭제 기준 추가 |
| 운영과 배포 | 스택만 있고 릴리즈 조건이 부족했음 | 비기능 요구사항과 릴리즈 게이트 추가 |

## 추가하면 좋은 기능

### P0에 포함

- 사용자 계정과 서버 권한 검증
- 모바일 입력 토큰 발급과 만료 관리
- 영수증 파일첨부 또는 외부 링크 메타데이터 관리
- 운영 설정값 분리
- 월간 리포트 지표 산식 고정
- CSV 내보내기 사유와 AuditLog 기록
- 정산 잠금과 관리자 수정 사유

### P1 이후 검토

- 수동 연락 기록을 더 확장한 운영 커뮤니케이션 타임라인
- 주민 및 링커 데이터 CSV 가져오기
- 문자 또는 알림톡 발송 연동
- 인쇄용 보고서와 PDF 자동화
- 행정 열람용 권한 분리 화면

## 아직 확정이 필요한 결정

- 프로젝트 스택 최종 확정
- 원 단위 정산 반올림 또는 절사 정책
- 영수증 저장 방식: 파일 업로드 또는 외부 링크
- 인증 방식과 사용자 초대 방식
- 리포트 기준일: `serviceDate` 또는 `returnConfirmedAt`
- 초기 주민 및 동행링커 데이터 이관 방식
