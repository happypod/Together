# Design Style Guide

백천마을 동행이동 OS의 화면은 고령 사용자와 현장 운영자가 함께 쓰는 내부 운영관리 도구다. 디자인의 최우선 기준은 장식성보다 가독성, 명확성, 실수 방지, 빠른 확인이다.

## 1. 디자인 원칙

### 1.1 밝고 안정적인 화면

- 전체 배경은 밝은 중립색을 사용한다.
- 핵심 작업 영역은 흰색 또는 매우 밝은 배경으로 분리한다.
- 과한 그라데이션, 장식용 배경, 복잡한 패턴은 쓰지 않는다.
- 어두운 대시보드 테마는 기본값으로 쓰지 않는다.

### 1.2 큰 글자와 명확한 위계

- 본문 기본 글자 크기는 모바일 17px 이상, 데스크톱 16px 이상을 권장한다.
- 고령자 직접 입력 화면은 본문 18px 이상을 우선한다.
- 줄 높이는 1.5 이상을 유지한다.
- 글자 간격은 기본값을 사용하고 음수 letter-spacing을 쓰지 않는다.
- 보조 설명은 작게 만들더라도 14px 미만을 피한다.

### 1.3 한 화면 한 목적

- 화면 상단에는 현재 대상, 상태, 다음 행동을 먼저 보여준다.
- 한 화면에 여러 목적의 버튼을 과도하게 배치하지 않는다.
- 주요 행동은 1개, 보조 행동은 2개 이하로 우선순위를 둔다.
- 위험 행동은 기본 버튼과 같은 색상이나 위치로 두지 않는다.

### 1.4 실수 방지

- 삭제, 취소, 정산 수정, 상태 예외 변경은 확인 단계를 둔다.
- 저장 전 필수값 누락을 즉시 알려준다.
- 저장 후에는 완료 상태와 다음 행동을 명확히 보여준다.
- 오류 메시지는 원인과 사용자가 할 수 있는 다음 행동을 함께 제시한다.

## 2. 색상 규칙

색상은 밝고 명확하되 한 가지 색 계열로만 화면을 채우지 않는다. 상태 구분은 색상과 텍스트를 함께 사용한다.

### 2.1 권장 토큰

| 용도 | 토큰 | 예시 |
| --- | --- | --- |
| 앱 배경 | `background` | `#F7FAFC` |
| 표면 | `surface` | `#FFFFFF` |
| 약한 표면 | `surface-muted` | `#EEF4F8` |
| 기본 텍스트 | `text-primary` | `#172033` |
| 보조 텍스트 | `text-secondary` | `#4B5B6B` |
| 경계선 | `border` | `#D6E0EA` |
| 기본 액션 | `primary` | `#1769E0` |
| 기본 액션 hover | `primary-hover` | `#1158C0` |
| 성공 | `success` | `#12805C` |
| 주의 | `warning` | `#B76E00` |
| 위험 | `danger` | `#C83532` |
| 정보 | `info` | `#007C9E` |

### 2.2 사용 규칙

- 기본 텍스트 대비는 WCAG AA 이상을 목표로 한다.
- 회색 텍스트는 너무 옅게 쓰지 않는다.
- placeholder는 설명을 대신하지 않는다.
- 색상만으로 상태를 표현하지 않는다.
- 위험 버튼은 빨간색 계열로 명확히 구분하고 기본 버튼 위치에 두지 않는다.
- 중요한 경고는 연한 배경색과 굵은 제목, 설명 문구를 함께 사용한다.

## 3. 타이포그래피

### 3.1 크기 기준

| 용도 | 모바일 | 데스크톱 |
| --- | --- | --- |
| 화면 제목 | 24-28px | 26-32px |
| 섹션 제목 | 20-22px | 20-24px |
| 본문 | 17-18px | 16-18px |
| 폼 라벨 | 16-18px | 15-16px |
| 버튼 | 17-18px | 16-17px |
| 보조 설명 | 14-16px | 14-15px |
| 상태 배지 | 14-15px | 13-14px |

### 3.2 문구 기준

- 짧고 직접적인 한국어를 사용한다.
- “처리되었습니다”보다 “저장되었습니다”처럼 사용자가 이해하기 쉬운 동사를 쓴다.
- 전문 용어가 필요한 경우 화면에서 같은 표현을 반복해서 일관성을 유지한다.
- 버튼에는 명령형 동사를 쓴다: 저장, 배정, 예약요청, 확정, 귀가확인, 정산완료.
- 부정확한 홍보성 문구나 과장 표현을 쓰지 않는다.

## 4. 레이아웃

### 4.1 모바일

- 단일 컬럼을 기본으로 한다.
- 상단에는 대상명, 날짜, 현재 상태를 보여준다.
- 하단 또는 폼 끝에는 주요 행동 버튼을 둔다.
- 목록은 카드형으로 전환하고 핵심 정보 3-5개만 먼저 보여준다.
- 상세 정보는 접기/펼치기 또는 섹션 구분을 사용한다.
- 가로 스크롤은 리포트 표처럼 피할 수 없는 경우에만 제한적으로 사용한다.

### 4.2 데스크톱

- 반복 업무 화면은 좌측 목록, 우측 상세 또는 상단 요약, 하단 작업 구조를 허용한다.
- 카드 안에 카드를 중첩하지 않는다.
- 대시보드는 KPI, 오늘 일정, 미처리 작업을 우선 배치한다.
- 넓은 화면에서도 내용이 과도하게 퍼지지 않도록 최대 너비를 둔다.

### 4.3 간격과 밀도

- 모바일 폼 필드 간격은 충분히 둔다.
- 관련 필드는 섹션으로 묶고, 섹션 제목을 명확히 둔다.
- 버튼과 입력 필드는 손가락으로 누르기 쉬운 간격을 둔다.
- 정보가 많은 화면은 필터, 상태 탭, 검색을 먼저 배치한다.

## 5. 컴포넌트 규칙

### 5.1 버튼

- 주요 버튼 높이는 모바일 48px 이상을 권장한다.
- 버튼 텍스트는 한눈에 행동을 알 수 있어야 한다.
- 아이콘만 있는 버튼은 익숙한 기능에만 사용하고 tooltip 또는 aria-label을 제공한다.
- 저장, 확정, 정산완료 같은 주요 작업은 아이콘+텍스트 또는 텍스트 버튼을 사용한다.

### 5.2 폼

- 라벨은 항상 보이게 둔다.
- placeholder만으로 입력 의미를 설명하지 않는다.
- 필수값은 라벨 또는 도움말에서 명확히 표시한다.
- 오류는 필드 바로 아래와 필요 시 상단 요약에 함께 표시한다.
- 날짜, 시간대, 금액, 연락처 입력은 모바일 키보드 유형을 맞춘다.

### 5.3 목록과 표

- 모바일 목록은 카드형을 기본으로 한다.
- 카드 첫 줄에는 대상명과 상태를 배치한다.
- 두 번째 줄에는 날짜, 시간대, 마을, 목적지처럼 판단에 필요한 정보를 둔다.
- 데스크톱 표는 고정 헤더, 명확한 정렬, 충분한 행 높이를 사용한다.
- 전화번호와 개인정보는 목록에서 마스킹한다.

### 5.4 상태 표시

- 상태 배지는 색상, 텍스트, 필요 시 아이콘을 함께 사용한다.
- 상태명은 `definitions.md`의 화면 표시명을 따른다.
- 예외와 취소 상태는 사유 확인 버튼 또는 요약을 함께 보여준다.

### 5.5 대화상자와 확인 화면

- 모바일에서 모달은 전체 화면 또는 하단 시트로 전환한다.
- 위험 작업 확인은 대상명, 변경 전 상태, 변경 후 상태를 보여준다.
- 확인 버튼과 취소 버튼은 충분히 떨어뜨린다.

## 6. 고령 사용자 UX 기준

### 6.1 이해하기 쉬운 흐름

- 현재 단계와 남은 단계를 명확히 보여준다.
- 저장 후 다음에 해야 할 일을 안내한다.
- 복잡한 한 화면보다 단계가 명확한 여러 섹션을 선호한다.
- 반복 입력은 이전 값, 기본값, 선택지를 적극 활용한다.

### 6.2 인지 부담 줄이기

- 같은 개념은 같은 단어와 같은 위치를 사용한다.
- 한 화면에서 색상, 배지, 아이콘을 과도하게 늘리지 않는다.
- 검색, 필터, 정렬은 기본값이 있어야 한다.
- 빈 상태에는 “무엇을 하면 되는지”를 짧게 보여준다.

### 6.3 접근성

- 키보드 이동이 가능해야 한다.
- 포커스 상태가 명확해야 한다.
- 텍스트 확대나 브라우저 줌 125%에서도 주요 UI가 깨지지 않아야 한다.
- 색각 이상 사용자를 고려해 색상만으로 상태를 구분하지 않는다.
- 스크린리더용 라벨이 필요한 아이콘 버튼에는 `aria-label`을 둔다.

## 7. 화면별 스타일 기준

| 화면 | 스타일 기준 |
| --- | --- |
| 관리자 홈 | 밝은 배경, 큰 KPI 숫자, 오늘 할 일 우선, 미처리 항목 명확화 |
| 주민 신청 등록 | 단일 컬럼, 큰 라벨, 필수 동의 체크 명확화, 민감정보 입력 금지 안내 |
| 신청 목록 | 모바일 카드형, 연락처 마스킹, 검색과 상태 필터 우선 |
| 그룹 상세 | 현재 상태와 다음 행동을 상단 고정, 멤버 카드와 픽업 순서 명확화 |
| 동행링커 배정 | 활동가능 여부와 교육/보험 상태를 명확히 표시 |
| 택시예약 확정 | 차량번호, 기사 연락처, 요금 입력을 큰 필드로 제공 |
| 운행상태 입력 | 큰 체크 영역, 단계별 확인, 저장 완료 피드백 |
| 귀가확인 | 주민별 확인 상태를 크게 표시하고 실수 방지 확인 제공 |
| 정산 | 금액 단위와 산식 결과를 큰 숫자로 표시, 수정 사유와 잠금 상태 명확화 |
| 월간 리포트 | 요약 지표 우선, 상세 표는 데스크톱에서 확장 |

## 8. 금지 패턴

- 작고 옅은 글자로 중요한 정보를 표시하지 않는다.
- placeholder만으로 필드를 설명하지 않는다.
- hover해야만 보이는 핵심 기능을 만들지 않는다.
- 아이콘만으로 중요한 상태나 작업을 표현하지 않는다.
- 장식용 그래픽, 과한 그라데이션, 복잡한 카드 중첩을 쓰지 않는다.
- 고령 사용자가 직접 쓰는 화면에 작은 체크박스나 촘촘한 테이블을 그대로 노출하지 않는다.
- 의료, 진단, 치료, 이송, 자동배차, 자동결제처럼 MVP 성격을 오해시킬 수 있는 문구를 쓰지 않는다.

## 9. 디자인 검증 체크리스트

각 UI 작업은 검증 기록에 아래 항목을 남긴다.

- [ ] 기본 텍스트와 버튼 텍스트가 충분히 크다.
- [ ] 중요한 정보의 색상 대비가 충분하다.
- [ ] 모바일 360px과 390px에서 주요 작업을 완료할 수 있다.
- [ ] 브라우저 줌 125%에서도 핵심 UI가 깨지지 않는다.
- [ ] 터치 대상이 충분히 크고 서로 붙어 있지 않다.
- [ ] 오류 메시지가 원인과 다음 행동을 알려준다.
- [ ] 상태는 색상과 텍스트를 함께 사용한다.
- [ ] 목록에서 개인정보가 마스킹된다.
- [ ] 고령 사용자에게 불필요하게 어려운 표현이 없다.
